# 雾锁王国修改器

单人游戏中，通过原生地图传送到灵火神殿、宝石锻炉、远古尖塔、古代方尖碑、地点、特殊探索点、任务感叹号和收藏品提示，支持游戏运行中启用和关闭

## 使用

先复制 config.example.json 为 config.local.json，填写游戏目录与存档目录的绝对路径，JSON 路径建议使用正斜杠
运行 build.ps1 构建后启动 EnshroudedTravel.exe，保留旁边的本地 payload 目录

1. 进入 backup 角色和 backup 世界，助手自动显示游戏 PID 并寻找传送数据
2. 首次定位显示扫描百分比、已处理/总内存量和耗时，可以取消；取消后会自动重新检查
3. 定位完成后点击「启用传送」，重新打开地图点击灵火神殿、宝石锻炉、远古尖塔、古代方尖碑、地点、特殊探索点、任务感叹号或收藏品提示
4. 点击「关闭传送」后重新打开地图，恢复原有行为
5. 点击「开启更小缩放」后重新打开地图，缩放档位变为 `16/8/4/2/0.45`；再次点击即可恢复
6. 点击「允许瘴气中传送」后，可在瘴气区域打开地图并使用快速传送；再次点击恢复原生限制
7. 点击「免费增大箱子」后，打开箱子并点击「增大」；在“增大箱子空间”界面升级不再消耗材料，也不受等级解锁限制；再次点击关闭即恢复材料与等级要求
8. 点击「白天」或「黑夜」后，游戏时间跳到对应时段中间并继续正常计时；当前世界约为 14:00 和 02:00，两个按钮只执行一次调整，不会锁定时间，关闭助手也不回退
9. 点击「伤害提升10倍」后，将玩家对非玩家目标的命中扣血值放大十倍，覆盖魔棒等法术；再次点击恢复，仅适用本地单人世界
10. 切回原角色、原世界之前先关闭传送；正常关闭助手也会恢复本次助手持有的改动

启用/关闭功能与手动调整使用独立分区
点击「启用全部」只会开启功能开关区中尚未启用的功能；白天、黑夜和伤害提升属于手动调整，不纳入启用全部

当前未实现自动核实角色与世界身份，世界卸载日志检查不能替代手动关闭
「备份存档」仍要求正常退出游戏，避免复制正在写入的存档

## 连接速度与进度

- 显示 PID 表示识别进程，按钮可用表示传送数据已经完整校验
- 冷定位优先扫描私有只读资源区，跳过映像、文件映射和可执行页；完整核验传送与缩放资源后即停止，缺少的功能才继续扫描私有读写区
- 2026-10-27 在已加载世界中移开两份定位缓存后，实测扫描 490 MB、定位耗时 0.42 秒；旧版同次游戏日志为 55.08 秒，但两次世界加载阶段不同，不代表固定加速倍数
- 同一次游戏运行期间，通过 `runtime-location.txt` 复用地址，复核进程启动时间、版本和完整注册表；实测重连 0.56–1.03 秒
- 重启游戏后旧缓存无效，仍使用上述分阶段扫描；本次未重启游戏测量，尚未交付跨重启固定指针链，资源未加载时仍可能需要较长时间
- 上述冷扫描仅用于传送与地图缩放；昼夜通过当前版本模块固定入口逐级读取，不扫描全进程，也不因缺少昼夜缓存触发冷扫描
- 进度按已处理内存字节计算，不是预计剩余时间；扫描中变为不可读的字节会单独记录

## 修改范围

适配 Steam Build 26082781，游戏目录由 config.local.json 的 gameDirectory 指定
存档目录由 config.local.json 的 saveDirectory 指定

界面开关修改进程内 `keen::MapMarkerRegistryResource` 中多类标记的传送字段
注册表长度 4652 字节，按 `markerId` 定位目标标记
目标字段为 `isFastTravelDestination`，开启值为 1，关闭时恢复模板原值
启用灵火精华、宝石锻炉、已解锁远古尖塔和全部 `Locations` 分类地点
`Locations` 包含特殊敌营、火盆、农场、村庄、矿点、幸存者营地和洞穴
继续启用已发现的瘴气巢穴、瘴气根、魔药之井和支线任务感叹号
古代方尖碑和放大镜/问号收藏品提示纳入同一传送开关
未解锁尖塔使用独立锁定标记，不纳入开关，也不会被提前解锁
所有目标只增加已发现标记的可传送属性，不修改解锁条件或揭露范围
每次写入前后核验完整注册表，仅临时调整目标页权限
缩放开关将进程内地图相机从四档扩展为五档
原生四档为 `16/8/4/2`，开启后第五档由原生 `0.7` 改为 `0.45`
资源字段位于地图界面资源偏移 `93476`，同时切换相机档位限制指令的单字节取值
关闭时先恢复四档限制，再将第五档恢复为原生 `0.7`
瘴气传送开关修改快速传送禁用判断的通用分支 `0xE793DE`
原生指令为 `JE`，开启时改为 `JMP`，关闭时恢复 `JE`
该开关只解除瘴气限制，下落和水中禁止传送仍保持原生行为
免费增大箱子只清零普通箱和魔法箱容量升级配方的材料数量和等级查询
普通箱覆盖 `16→24→32→40→56`，魔法箱覆盖 `24→32→40→56`
7 个容量升级配方的等级/知识查询会同时清零，新存档也可逐级升满
箱子附魔配方、其他制作配方、容量上限和升级后的箱子模板均不修改
免费增大箱子首次启用时定位私有只读资源区中的配方注册表，定位后复用本次游戏进程地址
缩放数据与传送注册表共用一次冷扫描，并按版本、PID、启动时间和完整资源校验复用缓存
地图缩放允许存在多份完整一致的内存副本，启用和关闭会同步修改并校验全部副本
不通过界面开关改写游戏资源或存档；游戏正常运行仍会自行保存

## 模块与构建

- `src/Services/RuntimeTravelService.cs`：进程定位、进度、缓存和内存开关
- `src/Services/RuntimeTravelService.TravelMarkers.cs`：多类地图标记 ID、字段偏移和状态匹配
- `src/Services/RuntimeTravelService.Zoom.cs`：地图缩放资源定位、最远档位切换和恢复
- `src/Services/RuntimeTravelService.ShroudTravel.cs`：瘴气传送限制切换和恢复
- `src/Services/RuntimeTravelService.StorageUpgrade.cs`：箱子容量升级配方定位、零材料切换和恢复
- `src/Services/RuntimeTravelService.DayNight.cs`：昼夜时间对象定位以及白天、黑夜调整
- `src/Services/RuntimeTravelService.DamageBoost.cs`：玩家命中伤害十倍切换、命中记录和恢复
- `src/Views/MainForm.cs`：原有桌面程序的运行中开关与定位反馈
- `src/Services/TravelService.cs`：版本/资源校验、存档备份；保留早期资源实验服务，当前界面不调用磁盘补丁切换
- `lab`：离线分析、独立构建与实验结果
- `backups`：已校验备份，恢复前必须明确时间，不能覆盖后续原存档进度

运行 `build.ps1` 使用 Windows 自带 .NET Framework C# 编译器构建
旧 `tests/Verify.cs` 对应历史磁盘版，不作为当前界面的验收程序
历史分析曾使用 kfc-parser，当前仓库未包含 vendor/kfc-parser，第三方工具及许可证需按实际依赖单独准备
