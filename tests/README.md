# 副本验证

依据：用户要求有界面、自动显示连接状态、启用灵火神殿地图传送、检测效果且不能破坏存档

测试数据：从首次通过校验的备份复制存档，从当前原版游戏复制资源，不在正式目录上写入

| 场景 | 操作 | 断言 |
|---|---|---|
| 精确补丁 | 对独立原版资源执行生产 Patch.Apply | 两个资源均达到 EML 实际生成结果的完整 SHA-256 |
| 界面运行态 | 创建真实主窗体并等待自动发现当前真实游戏 | 连接状态包含真实 PID，启用、恢复、备份按钮禁用 |
| 运行中保护 | 调用真实 Toggle | 报 GAME_RUNNING，副本资源和存档未变化 |
| 完整往返 | 游戏退出后从界面点击启用再关闭 | 原版→实际补丁→原版，界面状态同步且存档逐个不变 |
| 中断恢复版本 | 写入操作标记后改变副本 EXE | 仍判版本不支持，不执行恢复 |
| 中断恢复外部变更 | 写入操作标记后改变资源副本 | 仍判资源不同，不覆盖未知资源 |

以上不等价于游戏内地图传送成功，落点和未发现地点过滤仍需在独立测试存档中实测
